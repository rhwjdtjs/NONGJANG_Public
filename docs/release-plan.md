# 개발·데모·출시 목표 계획

[문서 처음](../README.md) · [전체 잔여 범위](roadmap.md) · [현재 검증 범위](development-and-validation.md)

**2026-09-20 최신 목표: 공개 데모 2027년 1~2월, Steam 얼리 액세스 2027년 3월.** 정식 1.0 출시일은 미정이며 얼리 액세스 진행·검수 결과로 산정합니다. 이 문서는 개발 목표를 정리한 것으로 상점 출시 예약이나 완성 보장을 의미하지 않습니다.

## 월별 작업과 결과물

|---|---|---|

월별 표는 작업 집중 순서입니다. 차량·멀티나 월드 작업을 해당 월까지 기다렸다가 시작한다는 뜻이 아니며, 선행 조건이 갖춰지는 대로 병행합니다. 결함 수정·재검수 시간을 각 단계 안에 확보합니다.

## 유지하는 데모 범위

**공개 데모는 현재 요청한 기능 전체를 포함합니다.** 내부 명세의 **24개 영역·160개 열린 완료 조건**을 일정 문서만으로 닫거나 삭제하지 않습니다. 생태·모든 동물 유형·교감·훈련·생활·사냥·건설·차량·2인 멀티·지도·저장·UI를 일부만 만들고 데모 완료로 처리하지 않습니다. 농사·작물은 기존에 명시한 후속 범위를 유지합니다.

전체 섬 꾸미기와 참조 기반 경관·재질·물·날씨·조명, 물 튐·흙·먼지·총구·불의 효과와 음향, 키마·패드·옵션·성능도 데모 공개 전 검수 대상입니다. 날짜를 맞추기 위해 이 범위를 EA 이후로 옮기지 않습니다.

데모에서 전체 기능 흐름을 검증하고, EA에서는 실제 이용자 피드백으로 콘텐츠 깊이·다양성·생태/생존 균형과 운영 안정성을 발전시킵니다. 1.0은 최종 요구·장기 균형·유지보수·출시 검수가 충족된 시점에 판단합니다.

## 공개 여부를 결정하는 다섯 조건

아래는 프로젝트의 검수 계획이며 현재 모두 통과했다는 뜻이 아닙니다.

1. **통합 실행 빌드:** 에디터가 없는 PC에서 설치·실행하고, 실제 섬에서 새 게임→정착→생존→교감·사냥·제작→사망·새 생명→이어하기를 개발자 치트 없이 진행할 수 있어야 합니다.
2. **저장·멀티·운반 일관성:** 서로 다른 두 PC·Steam 계정에서 방문·귀환·지연·중단·재접속을 확인합니다. 아이템·동물·사람 운반, 트렁크, 각성·사망, 관계와 소유권을 저장·복원하며 복제·유실·저장 손상을 해결해야 합니다.
3. **전체 기능과 표현:** 전 종의 욕구·공격/도주·교감·명령·사육, 차량과 생활 흐름뿐 아니라 전체 섬 경관·그래픽·날씨·VFX·음향·UI·입력을 같은 빌드에서 확인합니다. 수면·사망의 접지, 장비 관통, 총구 발생점도 실제 화면으로 비교합니다.
4. **장기 생존과 성능:** 여러 게임 날짜의 생태·자원, 원근 전환·스트리밍·메모리와 저장 반복을 검수합니다. PC 사양·해상도·옵션·DLSS 상태와 성능을 기록하고, 설치 가능한 Windows 후보 빌드에서 진행 차단·반복 충돌을 해결합니다.
5. **EA 전환 준비:** 데모의 차단 결함과 중요한 피드백을 반영하고, 현재 구매 가치·저장 호환·업데이트·오류 제보와 복구 경로를 준비합니다. 3월이라는 날짜만으로 판매를 시작하지 않습니다.

소스 작성, 자동 검사 수, 공개 문서와 목표 화면 이미지는 실제 플레이·현재 빌드 촬영·통합 실행물의 검증을 대신하지 않습니다.

## 일정 점검과 병행 개발

이 일정은 사용자가 제시한 2027년 1~3월 공개 목표를 기준으로 합니다. 실제 주간 투입 시간과 통합 완료 속도는 아직 충분히 측정하지 않았으므로 실행 가능성을 이미 검증했다고 단정하지 않습니다. 초기 2주부터 실제 투입 시간·통과한 완료 조건·다시 열린 결함을 기록하고 매주 남은 의존성을 확인합니다. 항목마다 크기가 다르므로 160개를 단순히 나눠 완성률이나 소요 기간을 계산하지 않습니다.

SINGULARITY의 2026년 말 데모·2027년 상반기 출시 목표와 작업이 겹칩니다. 두 프로젝트의 실제 지원·수정 소요를 함께 기록하며 주간 계획을 조정합니다. 10월 말 핵심 흐름, 11월 말 전체 통합, 12월 말 공개 후보의 실제 결과로 다음 목표를 재평가합니다.

데모 조건이 부족하면 비공개 시험을 이어가고 수정 목표를 알립니다. 데모가 2월 말로 늦어지면 3월 EA까지의 피드백·안정화 기간을 다시 판단하며 검수 단계를 생략하지 않습니다. 공개를 막는 결함이 남으면 EA도 조정합니다. 1.0 날짜는 EA의 실제 결과를 확인한 뒤 정합니다.
