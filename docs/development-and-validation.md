## Codex 협업과 이후의 유지보수

TEAMNIRIZ의 1인 개발 프로젝트로 요구사항과 게임 방향을 정하고, Codex를 활용한 바이브코딩으로 C++ 시스템·에디터 작성 도구·데이터 연결·검증 스크립트의 기반을 구축합니다. 이후 개발자가 직접 코드와 수치, UI, 애니메이션을 수정하고 기능을 확장할 수 있도록 역할별 파일과 편집 경로를 문서화합니다.

```mermaid
flowchart LR
  A["개발자의 방향·요구 결정"] --> B["명세와 완료 조건"]
  B --> C["Codex 협업 구현·데이터 연결"]
  C --> D["자동 검사"]
  D --> E["실제 엔진 장면·재실행 검수"]
  E --> F["실패 원인과 수정 기록"]
  F --> C
  E --> G["편집 경로·미완료 문서화"]
  G --> H["개발자의 유지보수·확장"]
```

현재 편집 구조의 근거는 `UNNAnimalData`의 `EditAnywhere` 설정, 종별 JSON, Animation Blueprint 작성 도구, 역할별 C++ 파일과 재현 스크립트입니다. 모든 설정을 이미 사용자용 편집 도구로 완성했다는 뜻은 아니며 설명서와 최종 수정 경로도 계속 정리하고 있습니다.

## 검증 층위를 분리

| 확인 방법 | 알 수 있는 내용 | 별도로 확인할 내용 |
|---|---|---|
| 소스 읽기 | 상태·분기·저장·표현 연결의 실제 구현 경로 | 해당 기능이 게임에서 자연스럽게 보이는지 |
| 자동 검사 | 특정 입력과 실패 조건에서 규칙·불변 조건 유지 | 모든 실제 장면·전체 플레이 완성도 |
| 렌더링 장면 | 포즈·메시·상호작용 UI·시각 결함 | 시간에 걸친 흐름과 저장·네트워크 상태 |
| 새 프로세스 재실행 | 메모리에 남은 값에 의존하지 않는 저장 복원 | 모든 장애 상황의 무손실 |
| 독립 프로세스 LAN | 실제 네트워크 연결·RPC·방문 저장 경로 | 다른 물리 PC·Steam 계정·출시 빌드 환경 |

문서나 코드 생성, 에셋 보유, 자동 검사 통과를 전체 기능 완료로 바꾸지 않습니다. 실패한 실행과 준비된 검수 조건도 성공 결과와 함께 남깁니다.

## 실제 결함에서 검사를 확장한 사례

**먹이 수령 중 회전:** 동물이 이동을 멈춘 뒤에도 회전을 계속해 손·입 접촉에 실패했습니다. 교감 예약에서 회전도 함께 정리하고, 실패 조건을 재현하는 회귀 검사를 추가했습니다. 접촉 허용 거리를 늘려 성공으로 처리하지 않았습니다. 자세한 흐름은 [동물 AI 문서](animal-ai.md)에 있습니다.

**방문자 재실행:** 새 게임 프로세스에서 접속 식별자가 달라져 기존 방문을 복원하지 못하는 상황을 확인했습니다. 일회성 연결 식별과 저장된 방문 자격을 구별하고, 최종 상태를 저장한 다음 반환하는 순서를 유지했습니다. 상세 인증값이나 개인 저장은 공개하지 않고 처리 책임과 검증 범위만 설명합니다.

**시각 검사와 수치 검사 분리:** 장비와 총구의 좌표가 설정돼 있거나 수면 시간이 유지된다고 해서 화면의 관통·부유가 해결됐다고 보지 않습니다. 보이는 총구와 이펙트의 같은 프레임 비교, 발·신발의 접지와 움직임은 별도 실제 장면 검수 대상으로 남깁니다.
